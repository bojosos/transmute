# fx runtime: non-obvious decisions

**Code arena.** A 1 GiB `MEM_TOP_DOWN` RWX reservation (every stub, region and thunk within rel32 reach), cut into 2 MiB chunks (arena.cpp). The first 64 KiB of chunk 0 holds the stubs and their unwind data; arena offset 0 is the lookup-miss stub.
- *Permanent chunks* hold the stubs, abi thunks, trampolines, host callbacks and adapters (`arena_allocate`): bump allocated, never freed, and never waiting for reclaim, because callers may hold the map lock.
- *Code chunks* hold translated regions (`code_allocate`), in two streams: *volatile* for JIT code of registered guest code memory (a guest JIT such as V8 discards it together), *stable* for everything else. Code grows up from a chunk's bottom (committed in 256 KiB steps) and tier-0 entry counters take counter pages down from its top. The Region and its arrays live in read-write metadata blocks the chunk owns. Each chunk keeps its regions sorted by address (`region_at`), counts its live ones, and counts allocations that install has not finished (`pending`).
- *Free chunks* are decommitted. `TRANSMUTE_FX_ARENA_MB` caps how much of the arena may be in use (default: all of it).

**Arena reclaim** (regions.cpp; design and measurements in docs/ALCHEMY_MEMORY.md, "The fx code arena: reclaim"). An invalidated region stays mapped until its chunk is reclaimed: threads still inside it, RSB entries dead code pushed after the kill scrub, a helper's return address and a link exit's field can reach it. A pass runs on the reclaimer thread (a runtime background thread, never a guest thread), under the exclusive map lock:
1. Victims are code chunks that are not current, have no allocation in flight, and are mostly dead: at most a quarter of their code is still live (a guest JIT leaves long-lived code, such as V8's copied builtins and hot functions, among the code it discarded, so few chunks die entirely). Their remaining live regions are evicted: killed as invalidation kills them, but counted as `evicted_regions`, not as invalidations. The guest code is unchanged; an evicted region comes back from the JIT's kept translations or the cache on its next miss. When free chunks fall below an eighth of the budget, chunks with the fewest live bytes (oldest first) are evicted too, until a quarter is free.
2. Every registered guest thread is suspended (`scan_guest_threads`, the `host::sample` seam). Its registers (general, rip, rsp, xmm), its host stack from rsp to the top, and its GuestContext (except the RSB) are scanned word by word; RSB entries into victims are repointed to `rsb_redispatch`. A word inside a victim pins it. Nothing is allocated or locked while threads are suspended.
3. Unpinned victims are decommitted and their metadata blocks released. Pinned ones are tried again by a later pass.
After step 1 nothing in the runtime reaches a victim (map, lookup table, links, pending exits and page lists dropped its regions), so only what a thread already holds can, and step 2 sees all of that. The scan is conservative: a stale word only delays reuse. Stale words were the common pin until two sources were removed. `ctx->exit_arg` (a link exit's field) is cleared once the dispatcher has read it. `clear_stack_residue` zeroes 8 KiB below the dispatcher after translations, and below `reclaim_run` before it waits, so frames a thread later blocks in don't inherit code addresses from finished lookups. `TRANSMUTE_FX_RECLAIM_TRACE=1` prints each pass and where its pins were found (thread, register or stack offset, context word).
- Triggers: taking a code chunk wakes the reclaimer (`reclaim_notify`). It runs a pass only if mostly dead chunks hold 16 MiB or an eighth of the code in use, or if free chunks are low.
- Tier-0 regions whose entries a tier-1 region all replaced are retired at install (`retired_regions`): their chunk counts them as dead, so reclaim may take it (evicting them then), but they stay on their pages, so a write there still kills them and interrupts threads inside them. An allocation that finds no free chunk waits for a pass with eviction (`reclaim_wait`, at most 30 s), and throws `bad_alloc` after three such passes.
- Install flushes the instruction cache only for reused chunks (a no-op system call on x64; fresh bytes never executed). Eviction leaves pages write-protected: a later guest write faults once, finds no region and gives the page back.
- Inactive host fibers' stacks are not scanned: a guest fiber switch goes through an abi thunk, whose frames hold no region address.
- Process exit: `runtime_prepare_exit` stops the reclaimer like the preloaders (`reclaim_stop`), and `runtime_exit_safe` checks that no pass is running.

**Lookup table.** 2^20 direct-mapped 8-byte slots: `(pc >> 22) << 32 | (entry - arena_base)`, with index `((pc >> 2) ^ (pc >> 22)) & mask`. Each slot is written with one aligned store (never torn) and compared against the full 64-bit tag, so non-canonical pcs never alias. An empty slot is 0, which decodes to the miss stub, so even a stray "hit" is safe. The encoding is published in `runtime.hpp` so the translator can inline it.

**Translation install.** Translations are serialized by a mutex, and lookups never wait on it. Install happens under the exclusive map lock. Writable guest pages are write-protected (SMC), then every guest word the translator read is re-read and compared. That check, not a global epoch, decides whether a racing write invalidated the translation, because a global epoch let unrelated invalidations starve translation. Cached regions have no reads to verify, so they use the epoch, with one attempt and then the JIT. The cache hashes the guest bytes before install write-protects the pages. A cached install that has to protect a writable page for the first time is therefore refused once, and the lookup is repeated under protection (one extra attempt). If the code keeps changing for 32 attempts, the instruction is interpreted, except exclusives and LSE atomics, which keep being retranslated. For a pc with several entries, the first translation keeps it. Linking is eager in both directions: exits whose target already exists are linked at install time, the rest wait in a pending list keyed by target pc and are linked when an entry for that pc is installed (a region, or a host entry). An exit restored by invalidation goes back to the pending list. The lazy `link` exit remains for races. Invariant (map lock): an exit has a `pending` reference exactly while its region is live and the exit is unlinked, and a `links` reference exactly while it is linked to the current map entry of its target. Killing a region removes both kinds, so nothing ever links into or out of a dead region. A thread still running dead code leaves it at its next exit; dead code may push RSB entries into itself after the scrub. Such a return re-enters the old translation once, as a stale loop would, until the `interrupt_pending` check. The pc/page/link maps are open-addressing tables with pooled lists: a node-based map spent most of the exclusive lock hold in the allocator (~9 µs per Blender region). For the same reason a region and all its arrays (entries, exits, fault sites, pins, fault maps, guest ranges) are one bump allocation from its code chunk's metadata blocks, freed with the chunk (the heap is hooked by the test machine's EDR: ~8 allocations per region cost about a third of a preloader's time). Install skips FlushInstructionCache except in reused chunks: x64 fetch is coherent with stores, fresh chunk bytes never executed, and the call is a ~0.5 µs system call per region.

**Preloading.** Once a module's main cache file is open, up to three background threads (hardware threads / 4; `TRANSMUTE_FX_PRELOAD=<n>`, 0 = off; Alchemy sets 0 in its child processes unless it is set) install its cached regions in file order, which is first-execution order, so guest threads mostly hit the lookup table instead of decoding and installing regions themselves. Work goes out in chunks of 32 records, round robin over modules in load order; a guest thread that still installs a cached region itself leaves a hint, and the next chunk continues from that record. Preloaded regions go through the same `install` as cached regions found on a miss (cache validation, epoch check). Startup measurements (warm tiny render): guest threads installed 10-15k cached regions themselves and waited ~70 ms for the map lock, mostly during DllMain/static initialization, while EcoQoS preloaders lagged and were preempted inside the lock. Now:
- The loader announces a module right after mapping it (`cache_module_mapped`), so its cache file is read while imports are bound; the ready handler (preloading) waits for `cache_module_loaded`, because install refuses code that is not yet registered guest code.
- Preloaders run at normal QoS until the queue first drains, then switch to background QoS (`TRANSMUTE_FX_BACKGROUND_QOS`).
- Lock-free probes replace map-lock lookups where an authoritative check follows anyway: `code_for_pc` probes the lookup table and leaves the map to `translate_and_install` (guest code) or `find_entry` (other pcs); `install`'s early "already installed" check probes the table while no tier-0 region exists; the preloader skips installed pcs by probe.
- Guest threads spin up to 50 µs on a contended map lock before blocking (holds average ~2 µs; an SRW wake-up costs far more), and preloaders step aside while one spins, then spin briefly among themselves. `TRANSMUTE_FX_STATS` prints the contended guest waits, preloader busy time and when the queue drained (`transmute-fx startup:`).
Result: init (DllMain/TLS) 110 → 42 ms, guest-thread translate time 113 → 16 ms, map-lock waits 70 → ~5 ms. `runtime_prepare_exit` (from `loader_process_exit` / `loader_process_terminate`, i.e. every guest exit path) parks the preloaders between two regions (bounded wait) before ExitProcess terminates threads, so none can die holding the map lock, the arena lock or a cache read epoch. After that, `module_ready` never touches the queue lock. In the process-detach hook (other threads gone), `runtime_exit_safe` try-acquires the map, translate, arena, registry, preloader and cache locks and checks cache epochs. A lock left by any terminated thread skips guest DLL_PROCESS_DETACH instead of deadlocking it (tests: `process_exit_*`).

**Invalidation** kills a region in this order:
1. Removes its map and table entries.
2. Restores every incoming link to its unlinked tail, and restores its own linked exits, so stale code cannot chain into other stale code.
3. Repoints RSB entries into it, in every context, to `rsb_redispatch` (`pc = x30; lookup`).
4. Sets `interrupt_pending` on every context, so threads leave stale loops.

Regions die when their guest bytes overlap the range, not when they merely share a page with it. A protected page gets its guest protection back only when no live region remains on it (a range ending inside a page, e.g. `flush_guest_code` from Darwin `sys_icache_invalidate`, keeps the regions outside it, and they must stay write-protected; giving the page back let a later store to them go unseen), and only if it still has ours. Callers that change protection (abi `VirtualProtect`) should invalidate before calling the host API. An SMC write fault still invalidates its whole page: the fault does not say how many bytes the store (or a host memcpy) will write.

**Guest code ranges** (`register_guest_code_memory`) are one sorted list of disjoint, non-adjacent ranges, published copy-on-write and never freed. Registering a range already covered, or unregistering one that is not registered, publishes nothing: V8 registers its 256 MiB code range again on every mprotect to executable.

**Enter/exit.** `enter(ctx, code, mxcsr)` saves the host callee-saved registers and xmm6–15, keeps the previous `host_rsp` for nesting, and loads MXCSR (skipped when unchanged). Before entering, the dispatcher clears the MXCSR-mirrored FPSR flags in `ctx.fpsr`, after encoding them in the MXCSR it passes. `dispatch_exit` returns the guest MXCSR, and the dispatcher folds its flags back into `ctx.fpsr` (the emit_fp protocol: FPSR = `ctx.fpsr | flags(MXCSR)`, so MRS FPSR is unchanged). A flag that guest or host code clears in MXCSR therefore stays cleared. `invoke`'s restore folds them back too when a C++ exception unwinds translated frames. `exit_to_dispatcher` lets a helper leave translated code without unwinding: helper frames are discarded.

**FP at host-code boundaries.** Host code reached from translated code without a dispatcher exit gets the architectural FPSR/FPCR in `ctx` (process.hpp contract, `fp_boundary.hpp`): the host-callback trampoline and the abi override thunks fold `flags(MXCSR)` into `ctx.fpsr` before the call and load MXCSR from `ctx.fpcr`/`ctx.fpsr` after it (ldmxcsr only when the value changes); `helper_check_interrupt` does the same in C++ (`fp_state_to_context`/`fp_state_from_context`) around interrupt requests. MXCSR is not written before the call, so its flags are stale while the host runs; `ThreadState::fp_host` marks that window (callbacks, interrupt requests, bracketed host entries) so that `exit_to_dispatcher` clears them instead of letting the dispatcher fold them in, and `invoke`'s C++-exception path skips its fold. `invoke` saves `fp_host`, clears it for the nested run and restores it. Tests: `tests/runtime_fp_boundary_tests.cpp`.

**Unwinding.** A function-table callback covers the whole arena, so host exceptions and stack walks pass through translated frames:
- enter stub and host-call bridge: precise unwind entries;
- abi thunks and trampolines: `abi_code_frame()`; the body is `[begin + prolog, begin + epilog_offset]`, inclusive, because a call's return address is often the epilog's first instruction;
- everything else: "rsp == host_rsp" (the enter-stub frame).

`invoke` restores `host_rsp` and MXCSR in a destructor, so a C++ exception thrown through guest frames leaves outer nesting levels intact.

**Faults (VEH).** Three cases:
- Write fault on a protected translated page: invalidate that page, restore its protection, retry.
- Execute fault at guest code from host code: redirect to the host-call bridge, with positional Win64 → AArch64 marshalling and the result returned in rax/xmm0.
- Fault inside translated code with a FaultSite: rebuild pins (GPR and XMM), flags and pc, stash the exception record, and resume at `dispatch_exit` with `ExitReason::raise`. The guest exception is then dispatched from the dispatcher, outside the handler.

**Guest stacks.** `GuestThreadStart::stack_reserve` is the usable reserve (0 = `guest_image_stack_reserve()`, else 1 MiB). It is fully committed, with a 64 KiB reserved guard region below it. The first fault in the guard region commits 60 KiB of emergency space and raises STATUS_STACK_OVERFLOW. The kernel only grows the *host* stack, so the VEH emulates growth for the guest stack: a `PAGE_GUARD` hit moves the guard down a page and the access is retried; reaching the guard region raises STATUS_STACK_OVERFLOW. This makes a guest-aware `_resetstkoflw` work. The host ucrtbase one operates on the host stack, so it needs an abi override. Fibers use `allocate_guest_stack` / `switch_guest_stack`.

**Thread teardown** runs from a PE TLS callback in `.CRT$XLB` on DLL_THREAD_DETACH. Two consequences:
- It runs after ntdll's FLS callbacks, so guest FLS callbacks reuse the thread's state, and guest DLL_THREAD_DETACH comes after them, as natively.
- It runs before the CRT's `thread_local` destructors, so the interpreter's per-thread engine is still alive during teardown.

`exit_guest_thread` therefore just calls `ExitThread`. The guest activation context (comctl32 v6) is activated on every thread that gets a context and stays active.

**Diagnostics.** Failures that are nearly always fatal print one line: illegal/unsupported instruction (with the interpreter's message), branch to non-code, misaligned pc, SVC without a handler. Each line gives the guest pc as module+offset, x30 and sp. Two environment switches add more:
- `TRANSMUTE_FX_TRACE_EXCEPTIONS=1` (or `trace_exits`): also prints every guest exception the runtime raises.
- `TRANSMUTE_FX_TRACE_HOST_EXCEPTIONS=1`: prints every exception the VEH sees, with a host backtrace for access violations.

Note that Git Bash shows a process exit code such as 0xE06D7363 as 127; check `$LASTEXITCODE` in PowerShell for the real value.

**Host callbacks.** `register_host_callback(pc, fn, user)` installs a host entry in the arena with the override-thunk call sequence. It keeps x30 in rbx, sets ctx.pc = x30, calls `fn(ctx, user)` with rsp == host_rsp (the generic arena unwind entry covers the call), then returns through the RSB to ctx.x[30], or jumps to `stub_indirect` if `fn` changed ctx.pc. Guest branches link to it like any host entry, so a call costs no dispatcher exit. `unregister_host_entry` removes host entries; invalidation never does.

**Hybrid CPUs (QoS).** Windows gives a new process launch QoS for about 3 s. After that, the threads of a process without a foreground window (Blender `-b` from a hidden or background console) get low QoS, and the Balanced policy on the i7-1355U moves a busy thread to E-cores. Native Blender does the same in long renders: at 25% it ran 22% on P-cores. A 3 s native render finishes inside the launch window, but the same render under fx outlasts it and ran ~80% on E-cores. `transmute-fx` therefore sets HighQoS on the guest process (`SetProcessInformation(ProcessPowerThrottling)` with EXECUTION_SPEED control and state 0; `TRANSMUTE_FX_QOS=high|default|eco`). It does this unless a parent already set an explicit state. Guest SetProcessInformation/SetThreadInformation calls still reach the host and override it. The preloaders, the cache journal writer and the background-AOT scheduler opt into EcoQoS (`TRANSMUTE_FX_BACKGROUND_QOS=eco|default`), and so does the `--aot-background` helper process. `TRANSMUTE_FX_CORESTATS=<file|1>[,<us>]` (corestats.cpp) measures the effect. Each interval it sends a special user APC to every thread that ran for at least a third of the last interval. The APC records `GetCurrentProcessorNumberEx`, and the report gives each thread's P/E share, context switches, QoS state and a timeline. The same source builds as a standalone DLL (`/DFX_CORESTATS_STANDALONE`) that native Blender can load through `ctypes`, so both are measured the same way.
